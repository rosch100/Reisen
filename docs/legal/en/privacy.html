Privacy Policy — Reisen

Last updated: August 2026

Controller

The Reisen app and this website are provided by Roland Schramme, Germany, as an open-source project at github.com/rosch100/Reisen.

Technical diagnostics for provider navigation, session checks, and auto-login contain redacted status/timing information and redacted URL metadata (host only, without path/query/fragment) during normal operation. Local detail diagnostics with structured DOM characteristics are stored only in a DEBUG build after explicit activation with the launch argument -ReisenDiagnosticsDebug, deleted after 24 hours, and share the local sync log (rotated at 256 KiB). These detail data are never included automatically in public error reports.

Fast electronic contact: public GitHub issues. For confidential data-subject requests (access, erasure), open an issue without trip data — we will reply with a private contact channel. Do not put passenger or booking details in the public issue text.

Summary

Reisen is a personal trip manager for iPhone, iPad, and Mac. Bookings stay on your device, optionally synced via iCloud. Sign-in with booking sites uses your own account with each provider. Reisen is not affiliated with Booking.com, Airbnb, Check24, Opodo, GetYourGuide, Traveloka, billiger-mietwagen.de, or other providers.

What data does Reisen process?

Paste import (optional, triggered by you)

You can paste text, an image, or a PDF of a booking confirmation into Reisen. Reisen extracts booking details from it and shows them for your review before you accept them.

  • Processing runs on device. If a build includes the corresponding Apple entitlement and the device offers Private Cloud Compute, processing may — only after your explicit confirmation for that individual import — use Apple Private Cloud Compute. Without that entitlement, processing stays on device only.
  • The pasted content is ephemeral: it is used only for the extraction and is not stored on the booking. For Share / “Open with”, it may briefly sit in an app-group handoff until the app consumes and deletes it.
  • No third-party LLM: the content is not sent to language models of other vendors.
  • If recognition finds no booking or fails with a model error, you can after confirmation create a public GitHub feature request. The original document is not sent to GitHub. When Mail is set up, the app opens an email draft with the document as an attachment to the feedback address; the document leaves the device only after you send that draft. If Mail is unavailable, the document remains on the device; only the public issue link (metadata, no attachment) is offered. Without confirmation the document does not leave the device.

Trips and bookings (entered or synced by you)

  • Trip names, booking details, confirmation codes, cancellation deadlines, manual entries, addresses of stays and stations
  • Travellers: given name and family name, optional date of birth (including minors if you or the provider record them)
  • Stored in SwiftData on device; optional mirroring in your private iCloud container iCloud.de.reisen.Reisen

Provider sign-in (optional)

  • Sign-in on third-party websites in a WKWebView with your own account
  • Session cookies remain in the device web view cookie store
  • Optional (opt-in, off by default): email and password after password login in the app device Keychain — not for Apple / passkey / OAuth sign-in. These credentials do not leave the device.

Calendar and reminders (optional, opt-in)

  • With your permission: calendar events and reminders for cancellation deadlines in Apple Calendar / Reminders (full access so entries can be updated and removed)
  • Local notifications via Notification Center (no marketing pushes)

Place lookup (MapKit)

To fill calendar locations and flight time zones, the app sends search or geocoding queries (e.g. airport IATA or hotel name) to Apple MapKit. Your GPS location is not collected.

Installed provider apps (on-device only)

On iOS, Reisen locally checks URL schemes to see whether a provider’s native app is installed and may pre-enable that provider once. This information is not transmitted.

Technical settings

  • App settings in UserDefaults (e.g. enabled providers, calendar choice)
  • No tracking, no advertising ID, no sale of data

Feedback and errors (optional)

If you send feedback or an error report, the app creates a public GitHub issue (text, app version, OS, device model, locale, time zone, architecture, memory (physical and process), available volume space if present, thermal state, low power mode, iCloud on/off, optional provider, optional GitHub username for attribution, and if present a truncated, redacted, zlib-compressed excerpt of local sync logs). Automatic error issues including crash stack traces only if you enable “Send errors automatically as a public issue” (consent, off by default). You do not need a GitHub account; the app uses an embedded issues-only token. Anyone can read the issue at github.com/rosch100/Reisen/issues. Obvious secrets and typical personal data in structured fields and labels (email, first/last name fields, phone numbers, addresses, dates of birth, booking references, IBANs) are redacted before sending; still do not include passenger data in feedback and do not rely on free-text name detection.

Email to reisenapp100@gmail.com is also filed as a public GitHub issue. The sender address and display name are redacted before publication; the message stays in the Gmail mailbox. The ingress marks processed messages as read; they stay in the Gmail mailbox and are not deleted automatically. Paste-import document emails (original as attachment) are not turned into issues; they remain in the mailbox with the attachment until the controller deletes them. App Store ratings and TestFlight feedback are processed by Apple; they are not turned into GitHub issues automatically.

Legal bases (Art. 6 GDPR)

  • Art. 6(1)(b): providing the app functions you request (local trip management, optional iCloud mirroring)
  • Art. 6(1)(a): consent for Keychain password storage, calendar/reminders/notifications, automatic public error issues
  • Art. 6(1)(f): legitimate interest in operating this information site and optional, user-initiated support via GitHub

You may withdraw consent in app or system settings; processing until withdrawal remains lawful.

iCloud / CloudKit

Sync uses Apple CloudKit in your iCloud account. Apple processes this data under the Apple Privacy Policy. You can delete local data or wipe iCloud data in the app settings.

Silent push notifications (iOS)

For CloudKit mirroring, iOS may receive silent background notifications (remote-notification). No visible remote push messages are sent to you.

Recipients and international transfers

  • Apple (US/EU): CloudKit, MapKit, EventKit, system services — see Apple’s privacy policy; Apple uses the EU-US Data Privacy Framework and/or Standard Contractual Clauses
  • Provider websites: When you sign in, their privacy policies apply (third-country transfers depending on the provider)
  • GitHub, Inc. (USA): only if you send feedback/an error report or visit this website; GitHub uses Standard Contractual Clauses (SCCs)
  • Google (Gmail): only if you email reisenapp100@gmail.com; Google’s privacy policy applies
  • No analytics service, no ad network in the app

Retention

  • Bookings, travellers, and settings: until you delete them in the app or reset local stores / wipe iCloud data
  • Keychain credentials: until you disable the feature or remove them in Keychain / Passwords
  • Calendar/reminder items: until you revoke permission or delete them in Calendar/Reminders
  • Public GitHub issues: per GitHub’s rules; we can close issues but cannot control third-party copies
  • Paste-import document emails (original as attachment; no GitHub issue): in the feedback Gmail mailbox until the controller deletes them — no automated deletion, no fixed period

Your rights

  • Access, rectification, erasure, restriction, portability, objection (Art. 15–21 GDPR)
  • Delete data in the app: local reset or “Also wipe iCloud data”
  • Provider passwords: can be disabled in app settings; stored accounts removable in Keychain / Passwords app
  • Calendar / notification permissions: revocable in system settings
  • Lodge a complaint with a supervisory authority; in Germany typically the Federal Commissioner for Data Protection and Freedom of Information (BfDI) or the competent state authority

This website (GitHub Pages)

The information site at rosch100.github.io/Reisen is hosted via GitHub Pages. When you visit, GitHub, Inc. processes technical access data (e.g. IP address, browser type, timestamp, requested URL) in server logs — per the GitHub Privacy Statement, among other purposes for security and service operation.

  • Retention: per criteria in GitHub’s privacy statement (purpose, legal obligations, dispute resolution); no fixed period under our control
  • Recipients: GitHub, Inc. (USA) and GitHub’s subprocessors (e.g. cloud infrastructure)
  • International transfers: processing including in the United States; GitHub uses Standard Contractual Clauses (SCCs) as described in their privacy statement
  • No first-party cookies, analytics, embedded third-party scripts, or external fonts on our static pages
  • No tracking or profiling by us; no cookie banner required for static content alone (GitHub’s technical processing as above)
  • Legal basis: legitimate interest in operating a public project and information site (Art. 6(1)(f) GDPR)
